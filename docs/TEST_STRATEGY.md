# Verification strategy
`npm test` includes unit tests plus integration tests against the real runtime PostgreSQL role. Coverage includes role grants/denials, date validation, signatures, MFA encryption/tamper detection, RLS, composite foreign keys, cross-tenant search/files/jobs, original download permission, CSRF, official-entry immutability, event-time identity preservation, append-only history/audit, independent approval/amendments, certificates/verification/revocation, membership/relationships/merge reversal, platform onboarding, session revocation and successful/single-use password recovery. It also verifies reviewed transcription import and idempotency.

`npm run test:e2e` uses installed Edge and synthetic accounts (Chromium in CI). It covers desktop login, module navigation, member search/draft creation, a 390px mobile drawer/overflow, full desktop/mobile axe scans including contrast, and uploading a synthetic PDF through manual source review to a draft-only import. Screenshots/traces go to ignored .qa/test-results folders. A passing script does not substitute for assistive-technology testing.

`tools/pdf-fixture.mjs` generates a synthetic two-page document. With the Docker worker running and shared data storage, `node --import tsx tools/check-pdf.ts` verifies two working-page jobs, local OCR text and normalised regions/confidence, original checksum preservation, and zero automatic official entries. It creates a dedicated synthetic tenant.

The API regression scenario also checks that an old recovery link cannot reactivate deactivated staff, explicit member denials cannot be bypassed through register/certificate responses, and a human-selected register type is saved consistently in drafts and reviewed OCR imports.

Before release: representative OCR evaluation, PDF/file fuzzing, successful/expired/reused token flows, privilege enrollment, quota/concurrency/failure testing, real SMTP delivery, MFA recovery policy, independent security assessment, 200% zoom, keyboard/screen-reader review and realistic load tests. PageSpeed Insights requires a publicly reachable deployment; no score is promised locally. Maintain version-schema regression fixtures as each diocese approves templates.
