# Data dictionary
See migrations/001_core.sql for exact columns, defaults, indexes and constraints.

UUIDs identify tenant-owned entities; created_at/updated_at are UTC timestamps. Event/birth dates are text plus precision to avoid inventing historical dates. `fields` is validated against immutable `register_schemas.fields` definitions. Core identity, dates, source and state have dedicated columns.

`tenants`: lifecycle and policy settings, storage/user quota. `users`: tenant identity, role, additive permission grants, Argon2 hash and encrypted TOTP. `sessions`: hashed random session key, CSRF secret and 8-hour expiry. `account_tokens`: hashed single-use invitation/reset tokens.

`organisations`: optional parent with same-tenant FK. `parish_units`: parish-scoped case-insensitive unique name and household membership through `households.unit_id`. `households`: directory fields, unit, draft/submitted/approved/rejected state, maker/submitter/reviewer, review note and optimistic revision; same-tenant composite foreign keys. Legacy free-text `unit` is retained for migration provenance, but API/UI use the joined unit name. `persons`: UUID, unique membership number, names/alternate script, precision, household, status, contacts and `photo_version`. `person_photos`: one private WebP bytea per member, tenant RLS, composite person foreign key and 512 KiB storage cap; replaced/deleted images are not retained in the active database.

`entries.event_year`: stored generated four-digit year for exact/year-only dates; null for approximate/unknown dates. Indexed with tenant, schema and status for year retrieval. First Holy Communion (`holy_communion`) and Burial (`burial`) default version-one schemas are installed for existing tenants and new tenants without overwriting customised schema versions.

`register_schemas`: kind, immutable version and field definitions. `entries`: typed subject, immutable event-time `subject_name` independent of the current person profile, reference, date, minister/place, custom fields, source asset/page/row, workflow actors, revision. `entry_versions`: immutable complete snapshots. `amendments`: proposed values, base revision, independent reviewers, reason and state; stale amendments cannot overwrite intervening corrections. `annotations`: separately appended official notes.

`volumes`: collection/series metadata, language, condition/custodian. `assets`: immutable filename/key, MIME, byte count, SHA-256 and upload source. `archive_pages`: immutable PDF working-page derivatives with ordering and source links. `ocr_jobs`: provider, human-correctable text and extraction, review actor, imported draft ID, attempt count/error. `ocr_results`: append-only recognised text, provider version, confidence and normalised word regions; human edits never overwrite original recognition output.

`certificate_templates`: church-approved wording and signatory. `certificate_issues`: immutable issuance snapshot, random public reference, revoke state and download counter. `audit_events`: actor ID and role snapshot, action/resource, protected details, UTC time and request ID. `security_events`: immutable account/security events. `mail_outbox`: encrypted setup tokens, bounded delivery attempts and delivery times. No passwords or tokens are logged.

`membership_history`, `household_memberships`, `person_relationships` and `person_merge_history` preserve movement, dated connections and reversible duplicate identity redirects. `users.denied_permissions` takes precedence over role defaults and extra grants. `certificate_templates.include_annotations` defaults to false and records the church-approved annotation disclosure policy. All content tables have tenant RLS and composite links. Every schema evolution lives in migrations/001–011.
